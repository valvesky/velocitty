# Velocitty
- DESIGN.md is the original design sketch, not a feature-completeness contract.
- Do not change the README.md
- Keep AGENTS.md up-to-date.
- Omarchy-first, (not) a terminal, with Windows and macOS ports through Peak. Executable is `src/main.zig`.
- User-facing branding says “(not) a terminal”; preserve technical terminal terminology and integration identifiers.
- Use Peak for windowing, input, clipboard, PTYs and process I/O on Linux (Wayland, then X11), Windows (Win32/ConPTY), and macOS (AppKit/POSIX PTY). Omarchy (Hyprland, themes, fonts, app menu) remains the primary Linux desktop.
- Pipeline: `circbuffer` (drain: tagged runs; content that can no longer be seen is fed without painting) → `vt` → `draw`.

# Release
- `zig build release` builds ReleaseFast for every target whose SDK is available (`-Drelease-os=linux|windows|macos` restricts it). Linux gnu (glibc 2.28 floor) and dynamically linked musl, x86_64 and aarch64, link libc (and libdl/libpthread/libutil on gnu); Peak compiles against host X11 and Wayland headers (`-idirafter /usr/include`) and dlopens Wayland, X11, Pulse, and xkbcommon at runtime. Windows x86_64-gnu cross-builds from Linux (manifest + `velocitty.rc` icon). macOS needs the native SDK or `-Dmacos-sdk=`; Peak is compiled with `.language = .objective_c` (a `-x objective-c` cflag is ignored because Zig puts cflags after the file).
- `zig build package` runs `scripts/package.py`: Linux `packages/velocitty-<version>-<triple>.tar.gz` (binary, desktop, icon, manpage); Windows portable ZIP plus Inno Setup installer from `scripts/windows.iss` (ZIP only when not on Windows); macOS universal `Velocitty.app` (ad-hoc signed) in a DMG, built on macOS.
- `.github/workflows/release.yml` builds, tests, packages and smoke-launches on Linux (gnu + Alpine musl under Xvfb), Windows (silent install → `tests/desktop_smoke.py` → uninstall) and macOS (mount DMG, `lipo -verify_arch`, launch) for `main`, `codex/**`, `release/**`, PRs and `v*` tags. `publish` runs only on `release/**` pushes or `v*` tags and uploads the unsigned release plus SHA256SUMS via `scripts/publish_release.py`. Release text is `RELEASE_NOTES.md`.
- Branding: `scripts/branding.py` regenerates `assets/icon.svg`, `icon.png`, `icon.ico`, `icon.icns` from the vector bolt path in the script, and the README wordmark/GIF via `ttfx` (`--icon-only` skips the wordmark).
- Windows ConPTY children get `STARTF_USESTDHANDLES` with invalid std handles; otherwise a child of a redirected parent writes to the parent's pipes instead of the pseudoconsole. Windows argv is quoted only when needed (cmd.exe ignores quoted switches like `"/c"`).

# Install
- `zig build` / `zig build install` is Zig's prefix install (default `zig-out/`: binary, `velocitty.desktop`, icon, manpage).
- `zig build install-usr` builds ReleaseFast for the host and installs `/usr/bin/velocitty`, `/usr/share/applications/velocitty.desktop`, the hicolor icon, and `/usr/share/man/man1/velocitty.1` so it appears in the Omarchy app menu. Uses `sudo` when stdin is a TTY, otherwise `pkexec`.

# Code Base
- Read files only when necessary. Use `grep` or `rg` if you only need a specific function.
- `simd.zig` — SIMD utilities.
- `debug.zig` — Debug-mode log + visual overlay (OSC 556 / CSI ? 556; ignored in Release). HUD: cursor, flags, dirty count `D`, last OSC `o`, `SYNC`/`NTF`
- `circbuffer.zig` — mirrored 64 KiB ring; `readSource`/`readPTY` (EOF or EAGAIN + 1/hz, never poll 0ms) never overwrite unconsumed bytes: below a quarter free they `drain` into a `Sink` (`VtState.sink()`; without a sink reading stops). `drain` is lossless for everything visible: after any input the screen, cursor, modes, pen, replies, palette and on-screen images equal an `exact` parse (history may lack lines that scrolled past). Pass 1 SIMD-skips to LF/VT/FF/SO/SI/ESC (and BS while reverse wraparound is on: it can move up a line) and writes runs (a text stretch is one `.text` run; escapes get a `Role`; SGRs and pen readers in `pens`), tracking the screen (alt-screen parameters apply in order), per-screen scroll region (with `decstbm`'s validation), DECOM and reverse wraparound from `View` (DECSTR/RIS reset them as the VT does); XTRESTORE (`CSI ? Pm r`) can restore any of these unseen, so a drain containing one makes no cut (`blind`). Pass 2 walks backward for a per-screen cut: the last barrier (ED 2, ED 0 right after CUP home with DECOM off, RIS, 1049 entered from the primary screen for the alt screen; ED 3, 47, 1047 and leaving the alt screen never clear) or `2*rows-1` full-region scrolling LFs with no upward/absolute motion after (from any row that many scroll every line out); screen switches and 1048 restores restart the count on both screens. Pass 3 (only with a cut) keeps every run: dead text and LFs get `ghost` (the VT moves the cursor without writing cells; with no image placements, a ghost LF at the bottom of a full-screen region does not scroll, and a ghost line ending in CR with no other controls, valid UTF-8, on the bottom row or with autowrap off, only sets column 0 and REP's character: `skipDeadLine`), graphics (sixel, kitty) are always fed in full (a dead placement still moves the cursor, replaces assigned ids, can be taller than the screen and is freed with its line), and dead SGRs are dropped only when a later dead full reset on the same screen (`CSI m`, a leading `0`, RIS) overrides them with no pen reader in between (DECSC, SCOSC, XTPUSHSGR, queries, DCS, alt-screen switches, 1048, clears).  Unterminated OSC/DCS/APC move to the spill buffer (grows geometrically to `max_spill`, 320 MiB, discarded through the terminator above it, compacted with `@memmove` after the feed, freed above 1 MiB when idle). Only the bytes already in the ring (at most one ring-full) are copied there (`openSpill`); while the string is open and the ring is empty, `readSource` reads straight into the spill's spare capacity (`directDest`/`spillRead`: reads no larger than the string so far, at least 4 KiB and at most the ring, so the copy of bytes after the terminator back into the ring stays small), searching only the new bytes for the terminator (an ESC at the end of one read pairs with `\` at the start of the next) and putting what follows it back into the ring; the finished string is marked `open.closed` (`pending()` is true) and the next drain emits it as a run with `flags.spill`, ahead of the ring bytes. Callers that only push into the ring (tests, `drainAll`) take the ring path (`continueSpill`) with identical runs. `Sink.feed` also receives the `*CircBuffer`; `takeSpill(allocator, off, len)` hands the whole spill buffer to the consumer of the run that ends it (≥ half a ring, no string open behind it, same allocator; the spill restarts empty); incomplete trailing CSI/ESC/UTF-8 (≤ 4 KiB) is held. `exact` feeds everything (reference parses). Ring size stays 64 KiB: 1 MiB+ adds lookahead but makes scan/VT 3-5x slower per byte (cache)
- `vt.zig` — minimal-state emulator; `feedFrom(runs, spill)` / `feedRuns` route text/C0/ESC/CSI/OSC/DCS/kitty; `.text` runs are split while feeding (`feedText`: 0x20..0x7E via bulk `printPlain`, C0/DEL via C0, non-ASCII runs via bulk `printUtf8` with inline `decodeUtf8`, falling back to `printCodepoint` for wraps/margins/insert/single shifts; stray high bytes are ignored: raw 8-bit C1 controls are not recognized in UTF-8); `rep` (CSI b) of plain ASCII goes through `printPlain`; `prepareImages` decodes images in view before a render (row-at-a-time fill; wrap, insert mode and DEC charsets fall back to `printCodepoint`)
- `grid.zig` — cell buffer (16-byte packed `Cell`; `fillCells` is the vectorized `@memset`), cursor, last-column flag (`wrap_pending`), scroll region, insert/delete; primary reflow on column resize (soft-wrap flags). Each ring row tracks `extent`/`tail`: cells past `extent` equal the blank it was last cleared with, so `clearRange` of a whole row only fills `[0, extent)` (every scrolling LF recycles a row). Print paths use `cellPtr` + `noteWrite`; mutable `getCell`/`rowSlice`, insert/delete, resize and recolors mark rows fully written (an untracked writer only costs speed). `lineIndex` replaces `% cap`
- `c0.zig` — C0 dispatch (BEL ignored; HT writes tab+spaces; BS reverse-wrap; LF/VT/FF are index only so terminfo `cud1` stays in column; NEL is CR+LF; cooked NL becomes CR NL via PTY `OPOST|ONLCR`; LCF delayed DECAWM wrap)
- `esc.zig` — ESC parse + charset G0–G3 / RIS / HTS / DECALN / SS2/SS3
- `csi.zig` — CSI parse (`;` params, `:` subparams, packed privates) + apply (foot ctlseqs: SGR, CUP, DECSET, DECRQM, rectangular, kitty kbd, window ops, color stack, XTSMGRAPHICS); debug-only CSI `? 556` overlay
- `osc.zig` — OSC 0/2 title, 4/10–12/104/110–112 colors, OSC 8 hyperlinks, 7 cwd, 9/99/777 notify (OSC 9;4 ConEmu progress and 9;9 cwd are not notify; OSC 777 only `notify;`; kitty OSC 99 `d=2` closes), 11 alpha, 17/19 selection, 22 cursor, 52 clipboard, 66 text, 133 marks, 176 app-id, debug-only 556 overlay (`all`/`off`/`grid,wrap,lcf,cursor,dirty,region,wide,hud`)
- `dcs.zig` — DCS DECRQSS (DECSTBM/SGR/DECSCUSR) + iTerm sync + XTGETTCAP + sixel (`sixel.zig`)
- `draw.zig` — CPU framebuffer; line-dirty fill + SIMD glyph blit; color-emoji RGBA blit; cell-span dirty when a prev snapshot exists; scroll reuse shifts pixels by the best-matching N-row offset (searched only when most lines are dirty; unmatched rows repaint); rows covered by kitty/sixel placements now or last frame repaint (not the whole screen), with clipped placement scaling; DECSCNM reverse; styled/colored underlines; C0 cells are not rasterized; Debug overlay (grid, wrap, LCF, dirty, region, wide, HUD)
- `type.zig` — TrueType rasterizer, coverage + RGBA atlas, bounded glyph cache (true LRU: hits on the glyph and render paths refresh recency; codepoint+style -> face/glyph resolve memo, 4096 direct-mapped, cleared on font changes); bold/italic faces; CBDT/CBLC color emoji (`type/cbdt.zig`); `type/eastasian.zig` cell width
- `scheme.zig` — TOML subset (colors, font, pad; hz/whitelist are legacy parsed settings with no runtime effect; cadence uses the Hyprland monitor rate or 60 Hz). Supported settings use bare table/key names and single-line strings, with basic escapes decoded; unrelated values, quoted names, array tables, multiline strings and nested collections are skipped without full TOML validation (collections are bounded to 64 levels). Integer settings parse directly into checked u32 values; finite font sizes accept exponents and digit separators. Loads Omarchy current theme; font size from Alacritty, then 9 pt only if the current theme's colors.toml is a regular file, otherwise 8 pt; family from fontconfig `monospace` (`omarchy font`). `[font].fallbacks` is an ordered array of up to 16 installed family names (128 bytes each), applied before built-ins; overlays replace the array, `[]` clears custom entries only
- SIGUSR1/SIGUSR2 or Omarchy theme/font file change reloads colors and font in `main.zig` (`fc-match` needs process environ so HOME/fonts.conf apply); custom and built-in Noto family resolution verifies the matched family so missing names cannot silently load an unrelated substitute; primary patterns keep fontconfig substitution. Linux distro DejaVu/Noto paths remain as defaults; do not hardcode app-specific/user font families.
- `loop.zig` — unused libxev-shaped scaffolding; the active loop is in `main.zig`
- `select.zig` — cell-stream selection over `vt.VtState` (drag, double-click word, triple-click line)
- `key.zig` — PTY key encoding: Shift+Tab CSI Z, modified arrows CSI 1;mod A, xterm modifyOtherKeys `CSI 27;mod;key~`, kitty keyboard protocol CSI u when flags are pushed; Delete is CSI 3~ (not DEL 0x7F, which the tty treats as backspace)
- `kitty.zig` — kitty graphics (APC G: stream + file/temp, `a=q` OK replies for icat); multipart encoded data capped at 16 MiB; file reads are nonblocking regular-file only, and file reads reopen pinned regular files through /proc/self/fd; temporary unlink is restricted to protocol-marked direct children of /tmp, /var/tmp, /dev/shm, or an absolute TMPDIR; sixel bitmaps placed through the same store. Images keep their payload (`Pending`: base64, file bytes, or a private-palette sixel body; `owned` is the whole allocation when `data` lies inside a handed-over spill buffer, freed by `Pending.free`). `VtState.feedOwned` gives `Store.feedDonor` a `Donor` for spill runs: a complete single-APC direct transmission (not `m=1` chunked) takes the ring's spill buffer (`takeSpill`, shrunk with `remap` when slack is large) instead of copying the payload into `chunks`, so the base64 is written once, by read(2); chunked transfers keep the single copy into `chunks` and `chunks` → `pending` stays a move and decode in `decodeVisible` only when a placement is in view; limits are kitty's (320 MiB and 10000 px per image) and 64 images, with no store-wide quota; a finished transfer moves out of `chunks` (no copy); size comes from `s`/`v`, the PNG IHDR, or `Sixel.measure` (other encoded formats and shared-palette sixels decode immediately). ED 2 (and ED 0 from home) drop the screen's placements; an image that has been placed (`placed`) is freed as soon as its last placement goes (history expiry, region scroll, ED 2/3, reflow, kitty delete); transmitted-but-never-placed images wait for a=p or delete (bounded by 64 images). Retransmitting an id drops its old placements. A failed lazy decode removes the image and its placements, and `draw.zig` skips images whose pixels are short. Placements are anchored to absolute lines (`Grid.base`, +1 per line pushed into history; oldest kept line is `base - (used - rows)`): history scrolls are O(1) (`expire` scans only once the oldest line reaches `min_end`), partial-region and alt-screen scrolls shift only placements overlapping the region (one partly above its top keeps moving until fully out), column-change reflow and ED 3 drop placements above the screen, and images draw in the history view
- `sixel.zig` — DCS q decoder (palette, repeats, raster attrs) → RGBA; `measure` is the same walk without painting (size only)
- `platform/` — Peak backend. `peak.zig` declares calls to vendored `vendor/godstack/Peak`; `build.zig` compiles its `peak.c`. Window + backbuffer present, focus/expose, WM_CLASS / xdg app-id (`--class` / OSC 176), opacity (X11 `_NET_WM_WINDOW_OPACITY`; Wayland `wp_alpha_modifier_v1`, else buffer alpha), clipboard CLIPBOARD plus primary (`zwp_primary_selection_v1` on Wayland). Wayland backbuffer is logical size × fractional scale (`wp_fractional_scale_v1` + `wp_viewport`; integer `wl_output` scale if those are absent) and pointer coordinates are in that buffer. Each commit sets `xdg_surface.set_window_geometry` and `wl_surface.set_input_region` to the logical size so a scaled buffer cannot take clicks outside the tile. The configure ack commits that clip immediately, without waiting for the next present, and pointer events outside the logical window are dropped (strict half-open bounds, rechecked for clicks/wheel after resize; extra mouse buttons are ignored rather than mapped to left-click). Temporary input regions are destroyed on the server after use. `peak_window_present_rect(y, h)` copies only those rows to the Wayland shm and sends `wl_surface.damage_buffer` (full damage when the shm is stale, opacity changed, or wl_surface < 4); X11 puts only those rows. Pointer events follow the entered surface; leave releases held buttons instead of extending the selection. Wheel is `wl_pointer` `axis_value120` / discrete, one click per detent. Cursor shape (OSC 22) is `wp_cursor_shape_v1` (text, hand, wait, crosshair, not-allowed, help) and hide uses `wl_pointer.set_cursor`. Motion is always delivered. PTY is `peak_pty_spawn` (`$SHELL` or `-e`); slave keeps `OPOST|ONLCR`; child env `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=velocitty`, `KITTY_WINDOW_ID`, `COLUMNS`, `LINES` is set around the spawn and restored in the parent; `TIOCSWINSZ` + `SIGWINCH` to the slave fg pgroup. Wayland compose is Peak's xkbcommon path; X11 text is `XLookupString` (no Multi_key compose). Keyboard text is retained per event; PTY writes queue on backpressure and flush in order without blocking. A key or paste while scrolled calls `viewBottom`
- `main.zig` — release builds allocate with `std.heap.c_allocator` (malloc reuses freed large blocks; `DebugAllocator` mapped and faulted fresh pages per image), Debug keeps `DebugAllocator` for leak checks; window + PTY + fonts (regular/bold/italic via fc-match, Noto Color Emoji fallback); `circbuffer` → `vt` → `draw` → Peak present (gated by `need_draw`; `Presenter` copies only the frame's damaged rows and calls `presentRect`, full blit + present when the window buffer, layout or pad color changed or after expose/resize); each tick `readSource` with `term.sink()` (EOF or EAGAIN+1/hz) pumps Peak during EAGAIN waits (successful reads are not deadline-bounded; full rings drain into the VT mid-read), then `drain` and `need_draw` from `circbuffer.fed`; `prepareImages` before `renderSel`; DECSET 2026 / iTerm DCS `=1s` defers present until sync ends (bounded by `hz` loop iterations, approximately 1s at intended cadence); mouse reports (1000/1002/1003 + SGR/urxvt/pixels) for buttons/motion/wheel, else alt-screen arrows or primary history view; Shift+Tab sends CSI Z (CSI 9;2u with kitty kbd); modified keys and kitty CSI u via `key.zig`; left-drag selects (Shift+drag when mouse reporting is on); double-click word / triple-click line (click chains and held/drag state reset on focus changes); mouse-up copies PRIMARY; Ctrl+Shift+C copies CLIPBOARD; Ctrl+Shift+V / Shift+Insert paste CLIPBOARD, middle-click pastes PRIMARY (bracketed if DECSET 2004); focus CSI I/O (1004) and visibility 2033; theme-change 2031 on palette reload (watchStamp throttled); inner pad from `[general] pad` (default 14), scaled by Wayland output scale; font/pad/cells use CSS 96 DPI × Hyprland/`GDK_SCALE` multiplier (not X11 mm-DPI) and re-apply on focus/resize only when scale/grid actually change; resize updates the grid, PTY winsize (SIGWINCH), real window pixel geometry (CSI 14/15/16), and flushes VT replies (in-band 2048 if enabled); CLI `-e`/`--` command, `--class=`, `--title=`, `--working-directory=` (xdg-terminal-exec)

# Bench
- `zig build bench` — `src/bench.zig`, ReleaseFast, ~13 s by default. Options: `--quick` (1 MiB/workload, 40 samples), `--mib`, `--burst` (KiB per frame), `--ring KIB`, `--no-spin` (skip spin-up for `perf stat -e instructions:u` comparisons; wall time on this laptop varies 4x between identical runs), `--grid COLSxROWS` (default 120x40), `--samples`, `--font`, `--only a,b`, `--help`. Every row is p50/p95/mean (nearest-rank over frames or 64-lookup batches). Header records Zig, CPU, AC/battery, governor and platform profile; a 500 ms spin-up precedes timing. `-Dbench-optimize=ReleaseSafe` builds the bench with safety checks.
- Pipeline workloads (`ascii`, `unicode`, `grapheme`, `csi-short`, `long-escape`, `kitty-image`, `sixel`, `pi`: pi 1.4 alt-screen frames with a 256x256 PNG): a writer thread streams generated bytes into a real raw-mode PTY slave; each frame reads one burst (default 16 KiB) from the master into the 64 KiB circbuffer, then `drain` (scan = drain minus vt) → `feedFrom` (vt) → `renderSel` (render) → framebuffer memcpy (present). Reports per-stage p50/p95 and share: io (time inside read(2); poll wait reported separately) / parse (scan+vt) / render (draw+copy). No Peak, compositor or input latency.
- `glyph` section: ASCII table, non-ASCII and CJK (fallback face) hits via `glyph()`/`peekGlyph()`, misses (raster+pack Latin, CJK, color emoji), uniform working sets at 0.5/0.9/1.1/2x the 2048-entry cache, and a hot-64 retention test (ideal LRU = 100% hot hits). `render` section: full/skip/single/line/cursor/selection/scroll/resize + present copy at the grid and ~4K.
- `kitten` section: kitty's `kitten __benchmark__` payloads (ascii, unicode, unique_unicode, csi, images = 1024x1024 RGBA in 128 KiB base64 chunks + `d=I`, long_escape_codes), `--mib` repetitions, headless 120x80, `exact`, MB/s; `--only kitten,csi` picks tests. This is the setup of the Ghostty comparison chart (M4 Max: ascii 618.6, unicode 914.7, unique 155.6, csi 224.5 MB/s, images 4.65, long escape 13.40 GB/s). Compare changes with `perf stat -e cycles` at `--mib 1` vs `--mib 21` (per-repetition parse cycles; wall time is unusable under load). `single_image` (kitten name): one 3840x2160 RGBA as ONE APC string (~44 MB base64, not chunked, transmit-only then `d=I`), the path that read-into-spill and `takeSpill` serve (user-mode cycles 146M → 88M, instructions 135M → 110M per run of `+terminal-stream` at `--mib 6`). The kitten rows and `+terminal-stream` read through `readSource` with a memory/fd source (`MemSource`/`StreamSource`; kitten timing subtracts the copy that stands in for read(2)). `image` section: one large PNG as pi sends it (`--image PATH`): transfer, decode on first draw (stb_image, the slow part), first/steady frames.
- `velocitty-bench +terminal-stream --data=PATH|- [--terminal-rows=80] [--terminal-cols=120] [--drop]` mirrors `ghostty-bench +terminal-stream`: reads the file (or stdin) in 64 KiB pieces into the ring, drains into the VT with every byte parsed (`--drop`: firehose dropping as the app), runs once, prints nothing, no fonts; time it externally. `zig build bench -- --only kitten --mib N --dump DIR` writes the kitten streams (`kitten-<name>.bin`) for both tools. Ghostty 1.4.0 builds it with Zig 0.17: `zig build -Demit-bench -Doptimize=ReleaseFast -Dapp-runtime=none`. Compare CPU time (user+sys), not wall, under load. `scripts/bench_vs_ghostty.py --ghostty-bench PATH [--reps 10] [--runs 5] [--metric cpu|wall]` does all of it (bench-install, dump, interleaved median runs) and writes `bench/vs-ghostty/results.json`, `chart.svg`, `chart.png` (dumbbell on a log axis, dataviz palette slots 1-2); `--chart-only` redraws from the JSON. `zig build bench-install` puts `velocitty-bench` in zig-out/bin.
- `drain` section: 4x `--mib` per workload from memory into the ring, drained at a quarter free (no PTY/render); scan and vt ns/B and `fed` (share of input bytes reaching the VT). `firehose` section: 16x `--mib` through a PTY read like main.zig; `scrn`/`images` say whether the final visible screen and placements equal an `exact` parse. `--only drain,csi-short` (or `firehose,…`) restricts those sections to the named workloads and skips their pipelines.
- Logs: `bench/<UTC>-<git12>[-dirty].txt` and `last_bench` (gitignored). Laptop power state moves numbers 1.5x+; compare runs only under the same power header.
- Benchmark checks: `zig test src/bench.zig src/type/stb_truetype.c src/stb_image.c -Ilib -lc --test-filter benchmark` (workloads parse completely with images reaching the store; PTY pipeline delivers every byte). `--test-filter "firehose drain"` checks that draining every workload ends with exactly the screen and images of a full parse. The bench PTY uses raw `linux.tcgetattr/tcsetattr`: `std.posix.tcsetattr` trips a safety check whose undefined behaviour corrupted the stack in ReleaseFast.

# Firehose regression tests
- `zig test src/circbuffer.zig src/stb_image.c -Ilib -lc -target x86_64-linux-musl` checks the drain: dead text fed as ghost (2*rows-1 LFs), every escape fed in a dead region, which clears are barriers (not ED 3, not home+ED 0 under DECOM, only 1049 entered from the primary screen), spill larger than the ring and over the cap, held CSI/UTF-8, dead kitty transfers fed in full. Output ingestion is lossy only through this tagging (DESIGN.md); it is separate from keyboard/paste delivery to the PTY.
- Differential contract: `zig test src/firehose_test.zig src/stb_image.c -Ilib -lc -target x86_64-linux-musl` feeds identical chunks to an `exact` ring/VT and a draining one (rings of 1024/4096 bytes; direct writes and `readSource` with a fake source) and compares the visible state after every drain: cells and soft-wrap flags of both screens, active screen, cursor/`wrap_pending`, pen, saved cursor, scroll region, flags/modes/charsets, saved modes, tab stops, palette, title (+stack), cwd/notify/clipboard, sixel state, kitty transfer state, every `reply` byte, and on-screen kitty/sixel placements (decoded pixels after `prepareImages`). History rows and `last_cp` are not compared. Contains named regression cases (all pass), split-at-every-byte sweeps and a seeded fuzz with a shrinker (prints seed, shrunk bytes and a tally of the first differing item). Also reached from `src/port_test.zig` (`zig build test`).

# Peak input regression tests
- Velocitty builds Peak with `PEAK_NO_GAMEPAD`: no direct `/dev/input/js*` polling. Gaming mice can expose joystick interfaces; converting their global button events into pointer events caused clicks at (0,0) in every terminal, bypassing compositor routing.
- Headless joystick-disabled regression: `cc -Ivendor/godstack/Peak tests/peak_no_gamepad.c -o /tmp/velocitty-peak-no-gamepad -ldl -lpthread -lm && /tmp/velocitty-peak-no-gamepad`.
- Headless Wayland hit-region, resize/click, extra-button, wheel, and leave tests: `cc -Ivendor/godstack/Peak tests/peak_pointer.c -o /tmp/velocitty-peak-pointer -ldl -lpthread -lm && /tmp/velocitty-peak-pointer`.

- Headless keyboard callback and wrapper regression: `zig test tests/peak_keyboard.c --dep platform -Mroot=tests/peak_keyboard.zig -Mplatform=src/platform/platform.zig -lc -ldl -lpthread -lm`. Wayland special-key identities use compositor xkb keysyms (not physical evdev codes), and repeat eligibility uses the keymap. Includes a real libxkbcommon `caps:swapescape` regression for press/release, modified Escape, and repeat (skips if libxkbcommon is unavailable).
- Headless Wayland partial-present regression: `cc -Ivendor/godstack/Peak tests/peak_present.c -o /tmp/velocitty-peak-present -ldl -lpthread -lm && /tmp/velocitty-peak-present`.
- PTY backpressure and ordering regression: `zig test tests/pty_queue.c --dep platform -Mroot=tests/pty_queue.zig -Mplatform=src/platform/platform.zig -lc -ldl -lpthread -lutil -lm`.

# Rendering tests
- Config checks: `zig test src/scheme.zig -lc -target x86_64-linux-musl` (integer precision/overflow, ignored TOML values and array tables, escaped strings, actual theme-file font defaults, fallback array order, ownership, overlays, empty reset, malformed input and limits). `src/main.zig` also tests rejection of unrelated fontconfig substitutions and real fallback order/deduplication, primary ASCII and symbol/braille glyphs. The loading smoke test explicitly skips if fontconfig or the two Noto Symbols families are unavailable.
