# Benchmarks
- `zig build bench` — `src/bench.zig`, ReleaseFast; runtime depends on the workload and host. Options: `--quick` (1 MiB/workload, 40 samples), `--mib`, `--burst` (KiB per frame), `--ring KIB` (default 1024), `--no-spin` (skip spin-up for `perf stat -e instructions:u` comparisons; wall time on this laptop varies 4x between identical runs), `--grid COLSxROWS` (default 120x40), `--samples`, `--font PATH` (explicit primary override; otherwise application font configuration), `--only a,b`, `--profile-obsolete` (drain timing in a `-Dbench-profile=true` build), `--help`. Every row is p50/p95/mean (nearest-rank over frames or 64-lookup batches). Header records Zig, CPU, AC/battery, governor and platform profile; a 500 ms spin-up precedes timing. `-Dbench-optimize=ReleaseSafe` builds the bench with safety checks.
- Pipeline workloads (`ascii`, `progress` (same-row ASCII/CR redraws), `unicode`, `grapheme`, `csi-short`, `long-escape`, `kitty-image`, `sixel`, `pi`: pi 1.4 alt-screen frames with a 256x256 PNG): a writer thread streams generated bytes into a real raw-mode PTY slave; each frame reads one burst (default 16 KiB) from the master into the 1 MiB circbuffer, then `drain` (scan = drain minus vt) → `feedFrom` (vt) → `renderSel` (render) → framebuffer memcpy (present). Reports per-stage p50/p95 and share: io (time inside read(2); poll wait reported separately) / parse (scan+vt) / render (draw+copy). No Peak, compositor or input latency.
- `glyph` section: ASCII table, non-ASCII and CJK (fallback face) hits via `glyph()`/`peekGlyph()`, misses (raster+pack Latin, CJK, color emoji), uniform working sets at 0.5/0.9/1.1/2x the 2048-entry cache, and a hot-64 retention test (ideal LRU = 100% hot hits). `render` section: full/skip/single/line/cursor/selection/scroll/resize + present copy at the grid and ~4K.
- `kitten` section: kitty's `kitten __benchmark__` payloads (ascii, unicode, unique_unicode, csi, images = 1024x1024 RGBA in 128 KiB base64 chunks + `d=I`, long_escape_codes), `--mib` repetitions, headless 120x80, `exact`, MB/s; `--only kitten,csi` picks tests. This is the setup of the Ghostty comparison chart (M4 Max: ascii 618.6, unicode 914.7, unique 155.6, csi 224.5 MB/s, images 4.65, long escape 13.40 GB/s). Compare changes with `perf stat -e cycles` at `--mib 1` vs `--mib 21` (per-repetition parse cycles; wall time is unusable under load). `single_image` (kitten name): one 3840x2160 RGBA as ONE APC string (~44 MB base64, not chunked, transmit-only then `d=I`), the path that read-into-stream and `takeStream` serve (user-mode cycles 146M → 88M, instructions 135M → 110M per run of `+terminal-stream` at `--mib 6`). The kitten rows and `+terminal-stream` read through `readSource` with a memory/fd source (`MemSource`/`StreamSource`; kitten timing subtracts the copy that stands in for read(2)). `image` section: one large PNG as pi sends it (`--image PATH`): transfer, decode on first draw (wuffs; off-frame in the app), first/steady frames.
- `velocitty-bench +terminal-stream --data=PATH|- [--terminal-rows=80] [--terminal-cols=120] [--drop]` mirrors `ghostty-bench +terminal-stream`: reads the file (or stdin) in 64 KiB pieces into the default 1 MiB ring, drains into the VT with every byte parsed (`--drop`: firehose dropping as the app), runs once, prints nothing, no fonts; time it externally. `zig build bench -- --only kitten --mib N --dump DIR` writes the kitten streams (`kitten-<name>.bin`) for both tools. Ghostty 1.4.0 builds it with Zig 0.17: `zig build -Demit-bench -Doptimize=ReleaseFast -Dapp-runtime=none`. Compare CPU time (user+sys), not wall, under load. `scripts/bench_vs_ghostty.py --ghostty-bench PATH [--reps 10] [--runs 5] [--metric cpu|wall]` does all of it (bench-install, dump, rotating/interleaved median runs of Velocitty exact, Velocitty `--drop`, and Ghostty exact) and writes `bench/vs-ghostty/results.json`, `chart.svg`, `chart.png` (three separate horizontal bars per workload with an independent zero-based linear scale (compare lengths only within a workload), aligned throughput values, and a Ghostty-relative comparison column. Ghostty uses a ghost emoji; Velocitty exact uses a lightning emoji and text skipping its RGB-inverted version, embedded from assets/benchmarks); JSON retains commands, raw CPU/wall samples, and round order for each mode. `--chart-only` redraws from the JSON, including older exact-only results. `python3 tests/ghostty_benchmark_test.py` checks mode selection, identical payloads, round rotation, and three-series/legacy charting. `zig build bench-install` puts `velocitty-bench` in zig-out/bin.
- `drain` section: 4x `--mib` per workload from memory into the ring, pressure-drained at a quarter free with the live suffix retained as lookahead, then frame-flushed at EOF (no PTY/render); scan and vt ns/B and `fed` (share of input bytes reaching the VT). `firehose` section: 16x `--mib` through a PTY read like main.zig (pressure consumption uses the lazy, cached isSpanObsolete predicate and retains live lookahead; normal frame consumption flushes it with skipping disabled; progress includes direct stream-buffer reads); `scrn`/`images` say whether the final visible screen and placements equal an `exact` parse. `--only drain,csi-short` (or `firehose,…`) restricts those sections to the named workloads and skips their pipelines.
- `zig build bench -Dbench-profile=true -- --only drain,progress --mib 4 --ring 1024 --profile-obsolete` explicitly times `isSpanObsolete`: every cold whole-span call and every prefix query, plus one in 64 remaining calls. The output separates raw `cold-ns`, `prefix-ns`, and `warm-ns` with call/sample counts, successful prefix proofs and omitted prefix bytes (including CR bytes inside the skipped prefix). Clock overhead is included; the warm total covers sampled calls only, and predicate time is already included in VT time. Use the default build without `-Dbench-profile=true` for uninstrumented throughput/instruction comparisons; it rejects `--profile-obsolete` with the required build flag. The application and default benchmark compile out the timing hook. `fed` counts consumed-run bytes including ghost or internally omitted text; it is not the share painted. The `progress` workload exercises long same-run CR overwrites; at least 120 columns keeps its updates non-wrapping.
- `python3 scripts/bench_startup.py --monstar PATH [--velocitty PATH] [--foot PATH] [--runs 100] [--warmup 5]` compares fresh-process startup/exit wall-time distributions in a live Linux Wayland session. All three executables default to PATH; select release builds explicitly. Runs `-e true` sequentially in seeded shuffled rounds, excludes warmups, retains every measured sample, and aborts on failure/timeout. Uses existing user configs and warm caches; includes shutdown and harness overhead, not first-frame latency. Windows may briefly appear/steal focus. Writes `bench/startup/results.json`, `chart.svg`, and optional `chart.png` in the Ghostty chart's light style; `--chart-only` redraws without launching terminals. JSON records commands, binary hashes, raw samples, round order, environment, and host metadata. Tests: `python3 tests/startup_benchmark_test.py`.
- `bash scripts/benchmark-pty.sh` measures kernel PTY throughput only (10 × 1 GiB by default); it does not exercise parsing, rendering, or presentation.
- Parser metadata is bounded to 160 KiB regardless of `--ring`; headers record `parser-metadata-max` and the selected ring. Worksets are reused across partial pressure feeds and normal frame flushes. `perf` over the entire firehose process also includes generation and the exact reference parse; peak RSS includes those fixtures/reference storage and is not application RSS. Parser-only `drain`/`kitten` selections and `+terminal-stream` load no font files or glyph atlases. Rendering selections load the configured primary and defer styled/coverage faces until requested; an explicit `--font PATH` overrides the primary.
- Logs: `bench/<UTC>-<git12>[-dirty].txt` (gitignored). Laptop power state moves numbers 1.5x+; compare runs only under the same power header.
- Versioned figures: `docs/design-1.3.html` uses the immutable `docs/velocitty-vs-ghostty-1.3.png` archive. The progress-proof instruction comparison belongs to `docs/design-1.3.1.html`, with captured samples in `docs/performance-1.3.1.json`. Regenerate its separate SVG/PNG using `python3 scripts/plot_axiom_benchmarks.py` (stdlib plus `rsvg-convert`); these are instruction counts against the preceding Velocitty implementation, not a new Ghostty throughput measurement.
- Benchmark checks: `zig test src/bench.zig src/type/stb_truetype.c src/image.c -Ilib -lc --test-filter benchmark` (workloads parse completely with images reaching the store; PTY pipeline delivers every byte). `--test-filter "firehose drain"` checks that draining every workload ends with exactly the screen and images of a full parse. The bench PTY uses raw `linux.tcgetattr/tcsetattr`: `std.posix.tcsetattr` trips a safety check whose undefined behaviour corrupted the stack in ReleaseFast.
